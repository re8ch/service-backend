# 2026-11-14 天翼语音网关八路外呼验收记录

## 验收目的

新版中国电信语音网关替换旧设备后，确认以下长期资产链路可用，并建立
可重复的逐路验收基线：

```text
R640 Stage-2 SIP/RTP
  -> MikroTik 192.168.88.0/24
  -> Grandstream GXW4108（8×FXO）
  -> 8 条 RJ11
  -> 天翼 MSG2600E-XES-8E8V-WS3（8×FXS）
  -> 中国电信 IMS/PSTN
```

测试日期为 2026-11-14，时区为 Asia/Shanghai。授权测试手机号码不写入
Git；本轮拨打省外手机，按运营商规则使用 `0 + 11 位手机号`。

## 设备与配置快照

### 天翼语音网关

- 页面型号：`MSG2600E-XES-8E8V-WS3`
- 管理地址：`192.168.1.1`
- 八个 IMS 用户均显示“注册成功”
- 八个本地号码均为“开启 / 业务正常”
- 验收前 1–7 口为空闲；8 口曾显示“锁定”，但随后实际外呼成功
- 未修改 IMS 服务器、账号、Voice 接口或拨号规则

### Grandstream GXW4108

- 地址：`192.168.88.249`
- 固件：`1.4.1.5`
- Stage Method：`ch1-8:2;`
- Local SIP Listen Port：`ch1-8:5060++;`
- 保存并重启后的端口调度：

```text
rr:1;rr:2;rr:3;rr:4;rr:5;rr:6;rr:7;rr:8;
```

原配置为 `rr:1;rr:2-8;`。它会把 2–8 口放进同一轮询组；因此分别向
5062、5064、5066 发起 SIP 会话时，手机仍可能看到同一主叫号码。发现该
现象后立即停止测试，拆成八个独立组，保存、重启并重新登录回读，确认
字段未回滚。

### R640

- 地址：`192.168.88.251`
- 诊断程序：`/opt/video-infra-src/scripts/gxw_stage2_call_test.py`
- 每路同时使用独立 GXW SIP 端口和 `99 + 线路号`选择码
- DTMF：RFC2833 telephone-event
- 每通先录制约 3 秒拨号音，发送 12 位号码，再保留约 25 秒呼叫窗口
- 每通结束发送 BYE，上一通结束后再开始下一通

## 已证实结论

1. 新版天翼网关的八个 IMS 账号分别注册，八个 POTS 口绑定八个不同号码。
2. GXW 的 `5060++` 实际对应 5060、5062、5064、5066、5068、5070、5072、
   5074；R640 gateway 配置与之对应。
3. `rr:2-8` 不适合固定线路资产；必须把八路拆成八个独立调度组。
4. line02 的“指定 SIP 端口 → 指定物理口 → 指定主叫号码”已由手机现场确认。
5. line02–08 均完成 SIP 建链、完整 DTMF、呼叫窗口和正常释放；这证明设备
   侧八路可用，但 03–08 的主叫号码仍需把手机来电记录作为最终审计证据。
6. GXW 的 `200 OK` 仍不能单独证明 PSTN 被叫到达；生产验收必须结合手机、
   RTP/录音或天翼统计。

## 复验步骤

1. 在天翼网关只读确认八个账号“注册成功”、本地号码“业务正常”。
2. 在 GXW 回读 Stage 2、`5060++` 和八个独立 `rr` 组。
3. 每次只测试一路；真实外呼必须获得授权，不把测试手机号码写入命令日志
   或 Git。
4. 省外手机使用 `0 + 11 位手机号`，本地手机直接使用 11 位号码。
5. 记录 UTC/本地时间、线路、SIP 端口、选择码、100/180/200/BYE、现场
   主叫号码、是否振铃/接听、双向音频、挂机释放时间。
6. 任一路主叫号码不匹配时立即停止后续测试，先检查 `rr` 分组和物理线序。

## 回滚

若独立分组导致异常，先停止真实呼叫并保存日志。回滚值为本次修改前的：

```text
rr:1;rr:2-8;
```

但该值会让 2–8 口轮询，不能作为固定号码生产模式。不要重置天翼网关，
不要批量注销 IMS，也不要修改运营商服务器。业务恢复优先使用普通电话机
直连相应天翼 FXS 口。
