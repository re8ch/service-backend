# 实验日志与已证实结论

## 物理话机基线

电信工程师和现场人员把普通电话机直接接到 A8-C，已验证可拨出、可接听。
这把故障边界缩小到 GXW4108 的 FXO 摘机、拨号音检测、DTMF 生成和节奏，
而非优先怀疑 A8-C IMS 注册。

## R640 到 GXW4108 的 SIP 建链

R640 从 `192.168.88.251:5160` 向 `192.168.88.249:5060` 发 INVITE。
GXW4108 依次返回 `100 Trying`、`180 Ringing`、约 10.8 秒后的 `200 OK`，
并从 5004/5012 等端口向 R640 的 40000/UDP 发送 G.711 RTP。

GXW User-Agent 证据：

```text
Grandstream GXW4108 (HW 2.0, Ch:1) 1.4.1.5
```

关键解释：`200 OK` 是 GXW 的 SIP/FXO 桥接状态，不是运营商侧被叫应答。

## 端口选择

- 不带固定端口且依赖 `rr:1-8;` 的测试曾实际落到 A8-C 第 8 口。
- 使用 `991 + 被叫号码` 后，GXW SIP User-Agent 报 `Ch:1`，A8-C 第 1 口
  的失败计数增加，证明已准确选中第 1 口。

## A8-C 统计

测试期间观察到：

- 第 1 口：主叫成功 0，失败最终至少 4 次。
- 第 8 口：失败 1 次（错误轮询到该口）。
- 时长均为 0。

被叫手机没有响铃。因此不能把 GXW 的 SIP 200 记作成功呼叫。

## 已排除或撤销的尝试

- A8-C 手机号段规则从 `1[3458]xxxxxxxxx` 扩成 `1[3-9]xxxxxxxxx`：
  无效，已完整恢复。
- GXW round-robin 从 `rr:1-8;` 改 `rr:1;`：
  老固件重启后自动恢复，未生效。
- 把 A8-C 主 Outbound 改到局域网：
  导致注册失败，不再采用；当前应保持电信主备地址。
- A8-C LAN1 策略路由去 IMS：
  不能替代 Voice_R_43 的运营商注册路径，不再作为主方案。

## 仍缺的证据

- FXO 摘机后 A8-C 是否给出稳定拨号音。
- GXW 是否真的在模拟线发送了全部 11 位 DTMF。
- 每一位 DTMF 的持续时间和间隔。
- A8-C 返回的是忙音、号码错误、超时还是其他回铃音。
- A8-C/GXW 两侧模拟电平、阻抗和断线监督是否匹配中国制式。

## 2026-07-30 Ch1 慢速本地 DTMF 实验

仅调整 GXW 第 1 口：

- Stage 1；
- 不等待拨号音；
- 摘机后延迟从 500 ms 增至 1500 ms；
- 关闭 RFC2833/SIP Info 参数继承，由 GXW 本地产生模拟 DTMF；
- 每位长度 150 ms，前 10 个数字间隔 150 ms；
- Syslog 指向 R640 并临时设为 DEBUG。

重启后重新登录核对，所有字段均已保留。使用授权测试号码执行一次固定
第 1 口外呼，真实号码不记录在仓库。

GXW DEBUG Syslog 证明：

- `FXO: Port: 0`，即物理第 1 口；
- 摘机约 1.68 秒后进入 `Ready for Dialing`；
- 完整生成 11 位 DTMF；
- 前 10 位均为 150 ms tone + 150 ms pause，末位为 150 ms tone；
- 随后状态依次为 `Dial OK`、`Remote Ringback`；
- 测试窗口结束收到 SIP CANCEL 后，端口恢复 `Idle`。

SIP 侧收到 `100 Trying` 和 `180 Ringing`，15 秒内没有收到最终 2xx，因此
测试脚本主动 CANCEL。A8-C 第 1 口主叫失败计数从 5 增至 6，成功仍为 0；
由于该次呼叫由测试端主动取消，失败计数不能单独证明被叫未振铃，但尚未
满足“实际接通并双向通话”的成功标准。

R640 证据：

```text
/tmp/gxw-ch1-tuned-20260730-120515.pcap
/tmp/gxw-ch1-tuned-20260730-120515.log
```

## 2026-07-30 Ch1 30 秒接听窗口实验

沿用慢速本地 DTMF 参数，将振铃窗口和 2xx 后保持时间分别设为 30 秒。
真实号码不记录在仓库。

- INVITE 后约 5.15 秒收到 `180 Ringing`；
- 约 10.89 秒后 GXW 返回 `200 OK`；
- 探针 ACK 后保持 30 秒，再发送 BYE；
- GXW 在约 1.5 ms 内确认 BYE，FXO 第 1 口恢复 On-Hook/Idle；
- A8-C 第 1 口主叫失败计数从 6 增至 7，成功仍为 0，通话时长仍为 0。

GXW 从 180 到 200 的约 10.9 秒时序与历史上的错误接通时序接近；结合
A8-C 成功计数和时长均未增加，设备证据不支持“运营商侧真实接通”。是否
曾实际振铃仍需由授权测试手机现场确认。

R640 证据：

```text
/tmp/gxw-ch1-answer-20260730-121804.pcap
/tmp/gxw-ch1-answer-20260730-121804.log
```

## 2026-07-30 Stage 2 首次音频诊断

现场确认上一轮手机没有实际振铃或接听后，将第 1 口切换到 Stage 2。
R640 探针先录制 3 秒音频，再逐位发送 11 位 RFC2833，最后继续录制
20 秒并发送 BYE。

关键结果：

- 探针成功保存 26.4 秒单声道 8 kHz WAV；
- GXW 收到并在模拟侧逐位拨出了完整号码；
- 音频开头约 3.9 秒存在稳定约 450 Hz 拨号音；
- 约 3.9–18.5 秒接近静音，18.5 秒后出现明显语音/提示音频；
- GXW 之后报告 `Remote Ringback` 和 `Remotely Answered`。

但是该实验不能作为第 1 口结论：GXW DEBUG 明确显示实际占用
`FXO: Port: 7`，即物理第 8 口。原因是官方的 `99 + 端口号`语法只适用于
Stage 1；Stage 2 下 Request-URI `991` 被忽略并进入 round-robin。发现后
已停止继续外呼。后续必须先建立 Stage 2 的固定端口方法，或物理隔离其他
FXO，才能再次测试。

A8-C 随后的只读核对进一步确认：

- 8 路 IMS 均为“注册成功”；
- 8 个本地 POTS 端口均为“开启 / 空闲 / 业务正常”；
- 第 1 口主叫失败累计 7 次；
- 第 8 口主叫失败从此前 1 次增至 2 次；
- 其他端口呼叫计数仍为 0；
- 所有端口主叫成功和通话时长仍为 0。

因此 Stage 2 首次实验确实落到了第 8 口。A8-C 注册与端口业务状态健康，
当前故障仍集中在 GXW 模拟拨号/端口调度和运营商收号结果，而不是 IMS
掉注册。

R640 证据：

```text
/tmp/gxw-stage2-20260730-122442.pcap
/tmp/gxw-stage2-20260730-122442.log
/tmp/gxw-stage2-20260730-122442.wav
```

## 2026-07-30 Stage 2 固定 FXO 1 验证

仅修改 GXW，将端口调度从 `rr:1-8;` 改为：

```text
rr:1;rr:2-8;
```

Local SIP Listen Port 保持 `ch1-8:5060++;`，SIP User Account Scheduling
保持关闭。设备重启后配置未回滚。

连续执行三次无号码 Stage-2 验证，均向 GXW UDP/5060 发 INVITE，只录制
3 秒拨号音，不发送 DTMF：

- 三次 Syslog 均为 `FXO: Port: 0`；
- 三次均进入 `Ready for Dialing`；
- WAV 时长分别约 3.00、2.98、3.00 秒，均有稳定非静音拨号音；
- 三次 BYE 后均恢复 On-Hook/Idle。

随后执行一次固定 FXO 1 的真实号码测试：

- 全程为 `FXO: Port: 0`；
- GXW 逐位拨出完整 11 位号码；
- GXW 报告 `Remote Ringback` 和 `Remotely Answered`；
- 授权测试手机现场确认没有来电；
- A8-C 第 1 口主叫失败从 7 增至 8，成功仍为 0，通话时长仍为 0；
- 36.4 秒 WAV 在约 18.6–24.8 秒出现运营商语音提示，之后出现规律的
  约 450 Hz 失败音；并非真实回铃或被叫语音。

结论：Stage-2 固定端口问题已经解决，剩余问题是 A8-C/运营商对完整 DTMF
号码的处理结果。GXW 的 `Remotely Answered` 仍是音调误判，不能用于业务
接通判断。

## 2026-07-30 外地手机前缀 0 验证成功

上一轮 WAV 中的运营商语音经现场辨认为“请在外地手机号码前加 0”。
保持 A8-C 完全只读、GXW 固定 `FXO: Port: 0` 及其余 Stage-2 参数不变，
仅在授权的 11 位测试手机号前增加 `0`，执行一次 30 秒真实外呼。

关键结果：

- GXW 在第 1 口逐位发送完整的 12 位拨号串；
- 授权测试手机实际收到呼叫，接听后现场确认听到链路音频，末尾有少量杂音；
- R640 收到并保存了 36.70 秒 PCMU 音频；
- 测试结束时探针发送 BYE，GXW 返回 `200 OK`；
- Syslog 明确记录 Port 0 执行 `Initiate Hang-Up`、`On-Hook` 并恢复 `Idle`。

结论：根因是运营商要求外地手机号码使用 `0 + 11 位手机号`，不是 GXW
丢失 DTMF。固定 FXO 1 的 Stage-2 外呼、被叫到达、接听侧音频和挂机释放
均已验证。当前探针只接收 GXW RTP，不向模拟侧发送话音，因此这次证据不
包含 R640 到手机方向的语音质量验证；末尾杂音也应在后续双向媒体探针中
单独评估。

R640 证据：

```text
/tmp/gxw-stage2-fixed-ch1-prefix0-20260730-125310.pcap
/tmp/gxw-stage2-fixed-ch1-prefix0-20260730-125310.log
/tmp/gxw-stage2-fixed-ch1-prefix0-20260730-125310.wav
```

## 2026-07-30 同地区手机不加 0 验证成功

保持 A8-C 完全只读、GXW Stage-2 固定 FXO 1 的配置不变，对用户明确授权的
娄底本地手机号执行一次不加 `0` 的 11 位直拨测试。

关键结果：

- GXW 接受 INVITE，并依次返回 `100 Trying`、`180 Ringing` 和 `200 OK`；
- 探针逐位发送完整 11 位号码，录制 3 秒拨号音及 30 秒拨号后音频；
- 测试手机实际振铃并接听，用户说了几句话后主动挂断；
- 36.38 秒 WAV 在约 22.83 秒开始出现语音，随后呈现多段语音和自然停顿，
  与现场“说了几句话然后挂断”的操作一致；
- 探针测试窗口结束时发送 BYE。

结论：同一地区手机号码可以直接使用 11 位号码，不需要前缀 `0`；此前
外地手机失败是运营商的长途拨号格式要求。


## 2026-07-30 固号入呼自动应答验证成功

首次从手机呼叫固号时，手机侧只听到固定频率回铃音并自动断线。R640 的
自动应答服务没有收到 INVITE。只读检查 GXW 后确认：

- Unconditional Call Forward User ID 为 `ch1-8:;`，第 1 口没有转发目标；
- SIP Destination Port 为 `ch1-8:5060;`，没有指向 R640 的 5160。

仅修改 GXW 第 1 口：

```text
User ID: ch1:autoanswer;ch2-8:;
SIP Server: ch1-8:p1;
SIP Destination Port: ch1:5160;ch2-8:5060;
```

保存、重启并重新登录后字段未回滚。A8-C 全程只读。

第二次现场入呼成功：

- GXW 从 UDP/5060 向 R640 UDP/5160 发送 INVITE；
- R640 自动应答器返回 `100 Trying`、`180 Ringing` 和 `200 OK`；
- GXW RTP 源为 UDP/5004，R640 提示音 RTP 源为 UDP/40002；
- 手机侧听到“已接收语音，即将挂断”；
- 提示结束后 R640 主动发送 BYE，GXW 返回 `200 OK`；
- 用户确认行为符合预期。

这证明第 1 路 PSTN → A8-C → GXW → R640 → GXW → A8-C → PSTN 的入呼、
下行提示音和主动释放闭环可用。

R640 证据：

```text
/tmp/gxw-inbound-autoanswer-20260730.pcap
journalctl -u gxw-sip-autoanswer.service
```
