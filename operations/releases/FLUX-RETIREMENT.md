# Local Flux controller retirement

The cloud SSA workflows own delivery and accepted-artifact replay. This change removes only the 22 native Flux Deployments and the local release compatibility projector/dispatcher from rendered desired state. Historical templates remain readable; final deletion patches in the main, federation and compatibility Kustomizations prevent either standalone component bootstrap or federation regeneration from restoring workloads. The legacy compatibility image promotion workflow is inert and its promotion command fails before any GitHub request. Product/controller implementation and cloud observer compatibility are separate work.

## Reviewed sources and writers

`flux-retirement-inventory.json` records all 24 exact Deployment UIDs, observed resourceVersions, desired replica counts and declaration paths. Main native templates come from `flux-system/gotk-components.yaml` and `retired-image-controllers.yaml`; four autonomous stacks come from `flux-federation/controllers.yaml`, generated by `operations/flux-federation/generate.py`; the two compatibility workloads come from `components/release-compat/controller.yaml`.

Read-only platform audit `op_f322d9736f8e4846a701028cbd44eb8a` found no Deployment ownerReferences. Managers were Flux bootstrap/recovery/kustomize, k3s and manual patch, with 22 native Deployments at zero replicas. Audit `op_4d5fb2b90d3c4e58876c739c6939d1ae` found no referencing CronJob/HPA specification or matching a1 k3s server auto-deploy manifest. This does not claim to enumerate arbitrary external administrators; no blanket RBAC or credential changes are part of this deletion.

## Runtime sequence (not executed by this PR)

1. Merge with successful checks. Confirm cloud compatibility migration and durable release state independently. Existing unhealthy Cilium/Advanced Fabric workloads are not prerequisites for deleting Flux and remain visible as unsynchronized/unhealthy.
2. Through the authenticated platform tool, re-read the exact 24 Deployments. Require the reviewed UID; stop on replacements, unexpected owners or target expansion. Re-read a fresh resourceVersion immediately before each mutation.
3. Stop dispatcher first, then compatibility controller, using a JSON Patch that tests metadata.uid and metadata.resourceVersion before setting spec.replicas to zero. Native Flux already has zero desired replicas. Wait for exact Deployment-owned ReplicaSets to have zero desired/current replicas and no active owned Pods. Do not change any business workload.
4. Serially submit native DELETE requests only to `/apis/apps/v1/namespaces/{namespace}/deployments/{name}` for the inventory. The body is `{"apiVersion":"v1","kind":"DeleteOptions","propagationPolicy":"Foreground","preconditions":{"uid":"<reviewed UID>","resourceVersion":"<fresh RV>"}}`. First validate the same body with `"dryRun":["All"]`; execution removes only that dryRun field after the migration gate is confirmed. The platform node channel supports `k3s kubectl delete --raw <exact path> -f -`, with the body on stdin; no local credential export is needed. A stale RV/replaced UID must fail closed, never fall back to name-only deletion.
5. Verify these Deployment identities are absent. Verify controller-owned ReplicaSets and Pods have exited/been removed by foreground GC; do not delete CRDs, paused Flux CRs, Release/ReleaseOperation history, Secrets, namespaces, business workloads or accepted-state ConfigMaps. Foreground deletion is confined to the controller-owned chain; no prune, force deletion or business-resource deletion.

The first inventory captured compatibility replicas 2 and dispatcher replicas 1; their observed RVs are evidence, not reusable authorization after quiescing. All 24 UID/RV-bound server DELETE dry-runs passed with Foreground policy in `op_0aacba417c334c789e309fa927e3b2ad`. No runtime scale or delete was performed while preparing this PR.

## Validation

A full root render compared with its base removes exactly 24 Deployments, adds nothing and changes no remaining object. Tests check all three render entrances, unique exact inventory, retained CRDs/history, paused/prune-disabled legacy owners and the disabled promotion path. Successful rendering is not runtime deletion evidence.
